# Escolher um modelo

| Recurso | Natureza | Pergunta útil | Limite |
|---|---|---|---|
| NIST CSF | Framework de resultados | Que resultados de gestão de risco buscamos? | Não fornece sozinho uma regra de detecção |
| MITRE ATT&CK | Base de conhecimento de comportamento adversário | Que comportamento foi observado? | Mapeamento não comprova atribuição nem eficácia |
| MITRE Engage | Framework de engajamento | Que objetivo defensivo guia o engajamento? | Não é um produto de honeypot |
| NIST SSDF | Práticas de desenvolvimento seguro | Que práticas incorporar ao ciclo de software? | Não certifica uma aplicação |
| TCEM | Método autoral do portfólio | Como ligar contexto a decisões defensivas rastreáveis? | Não é norma externa ou certificação |

Consulte as [fontes](REFERENCIAS.md) e o [TCEM](https://github.com/Ridd1kulusC0d3r/Cyber-Threat-Context-Modeling). Registre a versão exata quando aplicar um modelo. Relações entre modelos devem indicar justificativa, granularidade e lacunas; não são equivalências automáticas.
