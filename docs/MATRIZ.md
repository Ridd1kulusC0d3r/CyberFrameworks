# Escolher um modelo

| Recurso | Natureza | Pergunta útil | Limite |
|---|---|---|---|
| NIST CSF | Framework de resultados | Que resultados de gestão de risco buscamos? | Não fornece sozinho uma regra de detecção |
| MITRE ATT&CK | Base de conhecimento de comportamento adversário | Que comportamento foi observado? | Mapeamento não comprova atribuição nem eficácia |
| MITRE Engage | Framework de engajamento | Que objetivo defensivo guia o engajamento? | Não é um produto de honeypot |
| NIST SSDF | Práticas de desenvolvimento seguro | Que práticas incorporar ao ciclo de software? | Não certifica uma aplicação |
| MITRE D3FEND | Base de contramedidas | Que defesa se relaciona ao comportamento? | Relação não garante cobertura |
| DeTT&CT | Framework de cobertura | Qual visibilidade/detecção temos frente ao ATT&CK? | Pontuação autoavaliada |
| Sigma | Padrão de regra de detecção | Como expressar a detecção sem depender do SIEM? | Exige tradução e ajuste ao ambiente |
| ACH (Heuer) | Método analítico | Qual hipótese tem menos evidência inconsistente? | Reduz, não elimina vieses |
| MITRE FiGHT | Base de ameaças 5G | Que técnica adversária é específica de 5G? | Parte é teórica/demonstrada em pesquisa |
| 3GPP TR 33.926 | Especificação (SCAS) | Que ameaças/ativos por função de rede 3GPP? | Garantia de equipamento, não detecção |
| TCEM | Método autoral do portfólio | Como ligar contexto a decisões defensivas rastreáveis? | Não é norma externa ou certificação |

Consulte o [catálogo completo](CATALOGO.md), as [fontes](REFERENCIAS.md) e o [TCEM](https://github.com/Ridd1kulusC0d3r/Cyber-Threat-Context-Modeling). Registre a versão exata quando aplicar um modelo. Relações entre modelos devem indicar justificativa, granularidade e lacunas; não são equivalências automáticas.
